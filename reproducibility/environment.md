# Reproducibility environment

This repository locks the rebuild inputs without storing model weights or
checkpoints. `requirements/runtime-cu130.lock.txt` contains the complete
300-package registry resolution and distribution SHA256 hashes for Python 3.12
on manylinux 2.34 x86-64. `requirements/native-cu130.txt` separately locks the
FlashAttention source distribution compiled locally, and `uv.lock` locks the
small tooling environment. Run `scripts/lock_environment.sh` only when
intentionally updating the runtime lock; normal setup consumes the committed
locks.

The original experiment `.venv` was removed before this manifest was created,
so this file is a reconstruction lock resolved on 2026-09-12 from
the surviving setup script, pinned source trees, and slime requirements. It is
not a retrospective `pip freeze`. Surviving logs directly confirm Python
3.12.12 and PyTorch 2.11.0+cu130; the setup asserts Transformer Engine 2.16.1.
This distinction matters for auditability even though future installs are now
fully pinned.

The setup intentionally excludes `flash-attn-4` and `torch-memory-saver` from
the registry lock, then builds their selected replacements from the versions or
commits above. It builds FlashAttention 2.8.3 and installs the pinned
torch-memory-saver source revision without allowing either source install to
re-resolve dependencies.
It intentionally overrides SGLang 0.5.13's TileLang 0.1.8 dependency with the
validated 0.1.9 CUDA wheel; this resolver override is checked in explicitly.
The custom SGLang router wheel is content-pinned in `setup_uv.sh` with SHA256
`c26d31b9decd4bef04c5c2bf72470e7660c2802b9599b885eb7c1dfbfbd9a4b5`.

## Host requirements

The validated machine information is in `reproducibility/hardware.json`. A
compatible rebuild requires Linux x86-64 with glibc 2.34 or newer, eight
homogeneous SM90 GPUs, a driver capable of CUDA 13, a host CUDA toolkit that
provides compatibility headers, `uv`, `git`, `curl`, `patch`, and build tools.
The Python/CUDA packages are locked; the Linux kernel and system compiler are
recorded but not containerized, so bit-for-bit native build identity is not
claimed.

## Integrity and limitations

`reproducibility/SHA256SUMS` authenticates every committed data snapshot,
per-sample evaluation file, the runtime lock, and experiment patches/configs.
Run `python scripts/verify_reproducibility.py` after cloning.

The final HF exports and 173 GB training checkpoints are deliberately absent.
They can be regenerated by training and export. Distributed CUDA kernels,
asynchronous scheduling, and generation requests without an explicit API seed
make training statistically reproducible, not bitwise deterministic; the
committed per-sample results are the authoritative record of the reported run.
